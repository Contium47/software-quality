## Test Design

### calculateDiscount

Перевірено розрахунок знижки та помилкові значення.

- ціна 100, знижка 10% - результат 90;
- знижка 0% - результат 100;
- знижка 100% - результат 0;
- ціна -10 - помилка;
- знижка 101% - помилка.

### validateQuantity

Перевірено допустимі та недопустимі значення кількості.

- допустимі значення від 1 до 10;
- значення менше 1;
- значення більше 10;
- нецілі значення.

Перевірено значення 0, 1, 2, 9, 10, 11, 1.5.

### getShippingCost

Перевірено основні гілки функції.

- -1 - помилка;
- 999 - вартість доставки 100;
- 1000 - безкоштовна доставка.

# Контрольні питання

1. Що таке Unit Testing?
Тестування окремих частин програми.

2. Для чого використовується test() у Vitest?
Для створення тесту.

3. Для чого використовується expect()?
Для перевірки результату.

4. Що таке assertion?
Перевірка очікуваного результату.

5. Що означає схема ААА (Arrange–Act–Assert)?
Підготовка даних, виконання, перевірка результату.

6. Що відбувається на етапі Arrange?
Підготовка даних для тесту.

7. Що відбувається на етапі Act?
Виконується функція, яку тестуємо.

8. Що відбувається на етапі Assert?
Перевіряється отриманий результат.

9. Для чого використовується describe()?
Для об’єднання пов’язаних тестів.

10. Для чого використовується toThrow()?
Для перевірки, що функція викликає помилку.

11. Чому виклик функції при використанні toThrow() передається всередині іншої функції?
Щоб функція виконалась під час перевірки.

12. Для чого використовується test.for()?
Для запуску тесту з різними даними.

13. Що показує Code Coverage?
Яку частину коду покривають тести.

14. Чому 100% Coverage не гарантує відсутність дефектів?
Тести можуть не перевіряти всі можливі помилки.
