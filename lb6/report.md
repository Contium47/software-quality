## Результати тестування

### TC-01. Успішна авторизація

**Expected Result:**

Після введення правильного логіна та пароля користувач успішно авторизується та переходить на сторінку каталогу товарів.

**Actual Result:**

Після введення логіна standard_user та пароля secret_sauce і натискання кнопки Login відкрилася сторінка inventory.html. На сторінці відобразився заголовок Products.

**Status:** Passed

### TC-02. Авторизація з неправильним паролем

**Expected Result:**

Після введення неправильного пароля авторизація не повинна виконуватися. На сторінці має відобразитися повідомлення про помилку.

**Actual Result:**

Після введення неправильного пароля система не виконала авторизацію та відобразила повідомлення про помилку: Username and password do not match.

**Status:** Passed

### TC-03. Додавання товару до кошика

**Expected Result:**

Після натискання кнопки додавання товару до кошика лічильник кошика повинен відобразити кількість 1. Доданий товар повинен відображатися на сторінці кошика.

**Actual Result:**

Після натискання кнопки Add to cart для товару Sauce Labs Bolt T-Shirt лічильник кошика відобразив значення 1. На сторінці кошика відобразився доданий товар.

**Status:** Passed

## Контрольні питання
1. що таке ui-тестування?
ui-тестування - це перевірка роботи інтерфейсу користувача.

2. чим e2e-тестування відрізняється від component integration testing?
e2e перевіряє весь шлях користувача, а component integration testing - взаємодію окремих компонентів.

3. для чого використовується playwright?
playwright використовується для автоматизованого тестування вебзастосунків.

4. яке призначення об'єкта page?
page - це об'єкт сторінки браузера, через який можна взаємодіяти з нею.

5. що таке locator?
locator - це спосіб знайти елемент на сторінці.

6. чим відрізняються getbyrole() та getbytestid()?
getbyrole() шукає елемент за його роллю, а getbytestid() - за спеціальним тестовим атрибутом.

7. для чого використовується await?
await використовується для очікування завершення асинхронної операції.

8. що перевіряє expect()?
expect() перевіряє, чи відповідає результат очікуваному значенню.

9. як працює автоматичне очікування?
playwright автоматично чекає, поки елемент стане доступним для потрібної дії або перевірки.

10. для чого використовується codegen?
codegen записує дії користувача та автоматично створює код тесту.

11. яку інформацію можна отримати через trace viewer?
trace viewer показує дії тесту, помилки, скриншоти та стан сторінки.

12. чому невдалий тест не завжди означає дефект застосунку?
причиною може бути помилка тесту або проблема середовища.

13. для чого потрібна ізоляція тестів?
щоб результати одного тесту не впливали на інші.

14. які переваги має автоматизація повторюваних перевірок?
вона економить час і дозволяє швидко повторювати перевірки.

15. чому важливо перевіряти не лише виконання дії, а і її результат?
щоб переконатися, що дія виконалася правильно.
